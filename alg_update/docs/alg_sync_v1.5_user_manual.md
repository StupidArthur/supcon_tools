# 算法同步工具 v1.5 用户手册

模拟"算法改版后，要让平台实例用到新版代码包"这件事：把本地新版 `.zip` / `.py` 文件上传到平台，并把原本在发布的算法重新拉起，让 Pod 拉到新包。**算法原本的发布状态不变**——已发布的就是已发布。

产物：`算法同步工具v1.5.exe`（单文件 exe，无需装 Python）。

---

## 1. 这是什么

算法开发者改完代码后，平台里那些**已发布**的算法实例还在跑旧代码。想让它们跑新版，传统做法是「进平台 → 取消发布 → 重新上传 zip → 重新发布」挨个手动点。本工具做的是：

- 把**本地目录里的 `.zip` / `.py` 文件名**和**平台算法 `sourcePath` 字段**做匹配（文件名必须完全一致才能命中）。
- 对命中的算法执行「取消发布 → 上传 → 编辑元信息 → 重新发布」4 步。
- 对原本未发布的算法只「上传 + 编辑」。
- 最终所有原本已发布的算法保持已发布，原本未发布的保持未发布。

工具**不会**：删除平台算法、修改算法名称/分类、改核数/副本数/位置（这些都是「算法发布工具」干的活）。

### 1.1 同步流程（每个命中算法）

**已发布的算法**：

```
取消发布 → 上传 zip/py 到 MinIO → edit_algorithm 提交元信息 → 重新发布
```

**未发布的算法**：

```
上传 zip/py → edit_algorithm 提交元信息
```

> 这里的 `edit_algorithm` 会把平台的 `type` 字段重新写成 `"{categoryOne}-{categoryTwo}"` 拼接。如果只想刷包但**不动平台任何字段**，用「算法同步工具_不编辑 v1.1」。

## 2. 怎么使用

### 2.1 启动

双击 `算法同步工具v1.5.exe`。窗口标题：`算法同步工具 v1.5  |  designed by @yuzechao`。

### 2.2 一次完整的同步流程

1. **把算法文件放到 `resource/` 目录**（exe 同级，默认就是这个；想换目录见 3.2）。
2. **填连接信息**（URL / Username / Password；HTTPS 才填 Tenant ID）。
3. **确认算法目录**（默认 `resource`，可点「浏览」改）。
4. **点「开始更新」**（红色按钮）。
5. **看扫描日志** — 日志会输出 `[连接成功] 登录成功，缓存 N 个算法` 和 `[扫描完成] 命中平台 X 个，需取消发布 Y 个`。
6. **看弹窗确认清单** — 自动弹出「确认更新」对话框，列出命中列表 + 需取消发布列表。
7. **点确定** — 工具按命中顺序逐个执行 4 步流程，「控制台输出」区实时打印每步的 OK/失败。
8. **看最终汇总** — 日志最后一行 `任务完成 / 命中平台: X 个 / 已发布待处理: Y 个`。

工具同时提供「**导出算法信息**」（蓝色按钮）：把当前缓存的平台算法完整字段写成 CSV，默认文件名 `{主机}_alg_info_{日期}.csv`，UTF-8 BOM 编码，Excel 直接打开。这个按钮与同步流程独立，可以在不同步时单独用。

### 2.3 停止 / 中断

工具没有「中止」按钮。点了「开始更新」之后只能关窗口，后台线程会跑到当前算法结束才停。每步都打日志，关窗口前先看日志确认跑到哪儿了。

## 3. 需要填写什么

「连接配置」区 4 个字段：

| 字段 | 默认值 | 必填 | 备注 |
|---|---|---|---|
| **URL** | `http://10.16.11.1:31501` | 是 | 平台 alg-manager-web 的 HTTP/HTTPS 地址 |
| **Username** | `admin` | 是 | 平台账号 |
| **Password** | （空） | 是 | **每次启动都要重新填**，不会记忆 |
| **Tenant ID** | （空，仅 HTTPS 显示） | HTTPS 必填 | URL 是 `http://` 时输入框自动隐藏 |

「更新配置」区 1 个字段：

| 字段 | 默认值 | 必填 | 备注 |
|---|---|---|---|
| **算法目录** | `resource` | 是 | 相对路径相对**当前工作目录**——exe 双击启动时一般是 exe 同目录；想绝对路径直接填 `D:\alg_files` 这类 |

## 4. 需要准备什么附件

### 4.1 算法目录里的文件

放在工具界面填写的「算法目录」里，默认 `resource/`。

| 项 | 要求 |
|---|---|
| **支持的文件类型** | `.zip` 和 `.py` |
| **文件名** | 必须**完全等于**平台里算法的 `sourcePath` 字段（包括扩展名、大小写）——这是匹配命中的唯一依据 |
| **目录递归** | **不递归**，只扫顶层 |
| **打包 zip 的格式** | 没有特别限制（`application/x-zip-compressed`），普通 zip 即可 |

### 4.2 一个示例 `resource/` 目录

```
resource/
├── spc_pid_identification_analysis.py
├── spc_pid_identification_analysis_train.py
├── spc_process_data_PID.py
├── valve_anomaly_detection_infer.zip
└── valve_anomaly_detection_train.zip
```

### 4.3 匹配规则（重要）

工具的匹配是**精确匹配文件名**：

1. 扫 `resource/`，拿到 5 个文件名。
2. 拿每个文件名去 `platform_algorithms[i].sourcePath` 里查。
3. 命中 → 进待处理列表（标记 `isExist=True`）。
4. 没命中 → 进「未命中」清单（在弹窗里能看到，但**不会被同步**）。

常见的"明明本地有但没命中"原因：

- 文件名拼错（少一个字符、多一个后缀）。
- 大小写不一致（Linux 平台会区分大小写）。
- 平台里这个算法根本没有（CSV 工具能新建，但同步工具不新建，得先在平台后台建好）。

## 5. 界面上怎么看、怎么判断该做什么

工具窗口分 4 块，从上到下：

### 5.1 「连接配置」区

详见第 3 章。点「开始更新」前确认 URL / 密码都已填。

### 5.2 「更新配置」区

- **算法目录**输入框 + 「浏览」按钮：默认 `resource`，点浏览能改成任意目录。
- **开始更新**（红色按钮）：**主操作**。点了之后会变灰，等后台跑完一轮才重新可点。
- **导出算法信息**（蓝色按钮）：**独立功能**。用来把平台当前所有算法（含字段）导出成 CSV。

### 5.3 「确认更新」对话框（关键判读点）

点了「开始更新」后工具会先做「登录 → 拉全量算法 → 扫本地 → 匹配」，然后弹出这个对话框：

```
URL: http://10.16.11.1:31501
─────────────────────────────────────────
命中平台的算法: 5 个
其中需取消发布再更新的: 3 个
─────────────────────────────────────────
算法列表:
  - spc_pid_identification_analysis.py  id=101
  - spc_pid_identification_analysis_train.py  id=102
  - spc_process_data_PID.py  id=103
  - valve_anomaly_detection_infer.zip  id=104
  - valve_anomaly_detection_train.zip  id=105
─────────────────────────────────────────
需取消发布的算法:
  - spc_pid_identification_analysis.py  id=101
  - valve_anomaly_detection_infer.zip  id=104
  - valve_anomaly_detection_train.zip  id=105
─────────────────────────────────────────
每个算法将按序执行：
取消发布 → 上传编辑 → 重新发布（已发布算法）
─────────────────────────────────────────
确认是否开始更新？
```

**怎么判读**：

| 看什么 | 怎么判断 |
|---|---|
| **命中数量** | 应该等于 `resource/` 里 `.zip` + `.py` 的数量；少了说明文件名没匹配上（见 4.3） |
| **需取消发布数量** | 等于命中里原本 `isRelease=1` 的算法数；这个数决定会不会真的改平台状态 |
| **算法列表** | 名字、id 对不对得上平台；如果弹出来一个不该同步的，**点取消**回去删文件 |
| **流程提示** | 「取消 → 上传 → 编辑 → 重新发布」是顺序固定的，没有别的模式 |

点「确定」→ 开始跑；点「取消」→ 任务停，回到主窗口，弹窗列表丢弃（`_clear_pending`）。

### 5.4 「控制台输出」区（执行过程的真实记录）

每个命中算法都会打一段同样的格式：

```
[1/5] 处理: spc_pid_identification_analysis.py  id=101  zhName=PID辨识分析
    取消发布...
    [取消发布 OK]
    上传文件: resource/spc_pid_identification_analysis.py...
    [上传 OK] upload success
    编辑算法...
    [编辑 OK] id=101, zhName=PID辨识分析, isRelease=0
    重新发布...
    [重新发布 OK]
    完成

[2/5] 处理: spc_process_data_PID.py  id=103  zhName=PID数据处理
    上传文件: resource/spc_process_data_PID.py...
    [上传 OK] upload success
    编辑算法...
    [编辑 OK] id=103, zhName=PID数据处理, isRelease=0
    完成

...

============================================================
任务完成
============================================================
  命中平台: 5 个
  已发布待处理: 3 个
```

**怎么判读**：

| 日志 | 含义 |
|---|---|
| `[取消发布 OK]` / `[上传 OK]` / `[编辑 OK]` / `[重新发布 OK]` | 这一步平台返回成功 |
| `✗ xxx 失败: <错误>` | 这一步失败，整个算法中断，后面算法还会继续跑，但这个算法没完成 |
| `[编辑 OK] id=101, ..., isRelease=0` | 编辑接口返回的最终状态；如果原本已发布但这里 `isRelease=0`，说明重新发布那步可能没成功，看「重新发布 OK」那一行的判读 |
| **末尾汇总** `命中平台: X 个 / 已发布待处理: Y 个` | 总数对得上「确认更新」对话框里的数字就算成功 |
| `(可能是登录已过期，请重新登录)` | 鉴权类错误（A0201/A0202/A0203/A0230），重启工具重新填密码 |
