# 算法同步工具_不编辑版 v1.1 用户手册

和「算法同步工具 v1.5」干同一件事（把本地新版代码包上传到平台并让已发布实例重新拉起），**但跳过 edit 元信息那一步**——本地文件名命中哪个算法，就只刷那个算法的代码包，**完全不动**平台的核数/副本数/发布位置/分类/type 字段。

产物：`算法同步工具_不编辑v1.1.exe`（单文件 exe，无需装 Python）。

---

## 1. 这是什么

「算法同步工具 v1.5」的轻量版。**什么时候用**：

- 只刷代码包（`.zip` / `.py`），不修改平台任何元信息。
- v1.5 在 `edit_algorithm` 那一步会把 `type = "{categoryOne}-{categoryTwo}"` 重新写一次，会顺带把平台的 `type` 字段改掉——如果不想动它，用这个工具。
- 想精确控制"我只换代码包、不动别的"。

**和 v1.5 的差异**：

| 步骤 | v1.5 | v1.1（不编辑版） |
|---|---|---|
| 已发布算法 | 取消发布 → 上传 → edit → 重新发布 | 取消发布 → 上传 → 重新发布 |
| 未发布算法 | 上传 → edit | 上传 |

注意：**已发布算法完成后仍然保持已发布**，未发布算法完成后仍然保持未发布——这点和 v1.5 一致。

---

## 2. 怎么使用

### 2.1 启动

双击 `算法同步工具_不编辑v1.1.exe`。窗口标题：`算法同步工具_不编辑版 v1.1  |  designed by @yuzechao`。

### 2.2 一次完整的同步流程

操作步骤与 v1.5 完全一致：

1. 把算法文件放到 `resource/` 目录（默认）。
2. 填连接信息（URL / Username / Password；HTTPS 才填 Tenant ID）。
3. 确认算法目录（默认 `resource`，可改）。
4. 点「**开始更新**」（红色按钮）。
5. 看日志：`[连接成功]` → `[扫描完成] 命中 X 个，需取消发布 Y 个`。
6. 弹「确认更新」对话框，看清楚再点「确定」。
7. 工具按顺序逐个算法执行 3 步流程（已发布）或 1 步流程（未发布）。
8. 看末尾汇总：`任务完成 / 命中平台: X 个 / 已发布待处理: Y 个`。

蓝色「**导出算法信息**」按钮独立可用，把平台当前所有算法（含字段）导出成 CSV。

### 2.3 停止 / 中断

没有「中止」按钮。点了「开始更新」之后只能关窗口，后台线程跑到当前算法结束才停。先看日志确认跑到哪儿。

## 3. 需要填写什么

「连接配置」区 4 个字段，「更新配置」区 1 个字段——和 v1.5 完全相同：

| 字段 | 默认值 | 必填 | 备注 |
|---|---|---|---|
| **URL** | `http://10.16.11.1:31501` | 是 | 平台 alg-manager-web 的 HTTP/HTTPS 地址 |
| **Username** | `admin` | 是 | 平台账号 |
| **Password** | （空） | 是 | **每次启动都要重新填**，不会记忆 |
| **Tenant ID** | （空，仅 HTTPS 显示） | HTTPS 必填 | URL 是 `http://` 时输入框自动隐藏 |
| **算法目录** | `resource` | 是 | 相对当前工作目录；想绝对路径直接填 `D:\alg_files` |

## 4. 需要准备什么附件

### 4.1 算法目录里的文件

| 项 | 要求 |
|---|---|
| **支持的文件类型** | `.zip` 和 `.py` |
| **文件名** | **必须完全等于**平台里算法的 `sourcePath` 字段（包括扩展名、大小写） |
| **目录递归** | **不递归**，只扫顶层 |
| **打包 zip 的格式** | 没有特别限制（`application/x-zip-compressed`），普通 zip 即可 |

### 4.2 匹配规则

和 v1.5 完全相同——**精确匹配文件名**。

常见的"明明本地有但没命中"原因：

- 文件名拼错（少一个字符、多一个后缀）。
- 大小写不一致（Linux 平台会区分大小写）。
- 平台里这个算法根本没建（同步工具不会自动新建，要去平台后台先建）。

未命中的文件只会在弹窗里列出，**不会被同步**。

## 5. 界面上怎么看、怎么判断该做什么

工具窗口从左到右 4 个区和 v1.5 几乎完全一样。**判读关键点是「确认更新」对话框里流程提示那行**。

### 5.1 「确认更新」对话框（关键判读点）

和 v1.5 的对话框长得几乎一样，唯一区别是流程提示那一行：

```
每个算法将按序执行（不编辑）：
取消发布 → 上传文件 → 重新发布（已发布算法）
上传文件（未发布算法）
```

**怎么判读**：

| 看什么 | 怎么判断 |
|---|---|
| **流程提示行** | 看到「（不编辑）」字样说明走的是 3 步流程（不调 edit 接口）；如果看到这行说明打开的是 v1.1，**不是 v1.5** |
| **命中数量** | 应该等于 `resource/` 里 `.zip` + `.py` 的数量；少了说明文件名没匹配上 |
| **需取消发布数量** | 等于命中里原本 `isRelease=1` 的算法数；决定会不会改平台状态 |
| **算法列表** | 名字、id 对不对得上平台；弹出来一个不该同步的，**点取消**回去删文件 |

### 5.2 「控制台输出」区

每个命中算法都打一段日志，**没有 `[编辑 OK]` 那行**（v1.5 有，本工具没有）：

```
[1/5] 处理: spc_pid_identification_analysis.py  id=101  zhName=PID辨识分析
    取消发布...
    [取消发布 OK]
    上传文件: resource/spc_pid_identification_analysis.py...
    [上传 OK] upload success
    重新发布...
    [重新发布 OK]
    完成

[2/5] 处理: spc_process_data_PID.py  id=103  zhName=PID数据处理
    上传文件: resource/spc_process_data_PID.py...
    [上传 OK] upload success
    完成

...

============================================================
任务完成
============================================================
  命中平台: 5 个
  已发布待处理: 3 个
```

**怎么判读**：

| 日志 | 含义 |
|---|---|
| `[取消发布 OK]` / `[上传 OK]` / `[重新发布 OK]` | 这一步平台返回成功 |
| `[编辑 OK]` 出现 | **不对**——v1.1 不调 edit 接口，看到这行说明打开的是 v1.5 而不是 v1.1，关掉换工具 |
| `✗ xxx 失败: <错误>` | 这一步失败；后面算法会继续跑 |
| **末尾汇总** `命中平台: X 个 / 已发布待处理: Y 个` | 总数对得上「确认更新」对话框就算成功 |
| `(可能是登录已过期，请重新登录)` | 鉴权类错误，重启工具重新填密码 |

## 附：什么时候用 v1.5，什么时候用 v1.1

| 场景 | 用哪个 |
|---|---|
| 算法代码改了，想让平台实例跑新版 | 两个都行，效果一样 |
| 只想刷包，不想改平台任何元信息（含 `type` 字段拼接） | **用 v1.1** |
| 想让平台自动重新写一遍 `type` 字段 | 用 v1.5 |
| 之前在平台后台改过 `type` 字段，不想被覆盖 | **用 v1.1** |
