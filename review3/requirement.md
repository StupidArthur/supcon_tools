# 组态调试、工程组态与实时运行重构需求文档

## 1. 需求目标

将工具顶部导航调整为三个独立 Tab：

```text
组态调试 | 工程组态 | 实时运行
```

取消“实时运行与 UA”下的二级 Tab，不再设置独立的“画面”页面。

---

## 2. 顶部导航

| Tab  | 功能                 |
| ---- | ------------------ |
| 组态调试 | 原“DSL 工程”功能，仅修改名称  |
| 工程组态 | 创建、打开和配置实时工程       |
| 实时运行 | 启停实时工程，查看实例和操作实时参数 |

三个 Tab 必须始终显示。切换页面不得导致当前工程丢失，也不得影响已经启动的实时服务。

---

# 3. 组态调试

## 3.1 调整内容

原 Tab 名称：

```text
DSL 工程
```

修改为：

```text
组态调试
```

## 3.2 功能范围

该页面现有功能保持不变，包括：

* 新建和打开单个 YAML 配置文件；
* 编辑 YAML；
* 执行仿真运行；
* 查看仿真数据和画面；
* 导出仿真数据；
* 保存或另存 YAML 文件。

本次不修改该页面的界面布局、数据结构和业务逻辑。

---

# 4. 工程组态

## 4.1 页面布局

未打开工程时：

```text
┌──────────────────────────────────────────────┐
│                                             │
│          [打开工程]    [新建工程]            │
│                                             │
└──────────────────────────────────────────────┘
```

打开工程后：

```text
┌─────────────────────────────────────────────────────────┐
│ 工程名称                         工程保存路径             │
├─────────────────────────────────────────────────────────┤
│ YAML 文件                                               │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 文件名 │ 副本数量 │ 校验状态 │ 操作                 │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ A.yaml │    2     │ 通过     │ 移除                 │ │
│ │ B.yaml │    1     │ 失败     │ 查看错误 / 移除      │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ [添加 YAML]                              [保存工程]      │
│                                                         │
│ YAML 数量：2    实例总数：3    工程状态：校验通过       │
└─────────────────────────────────────────────────────────┘
```

页面不显示：

* 完整实例列表；
* 报警规则。

---

## 4.2 新建工程

用户点击“新建工程”后：

1. 输入工程名称；
2. 选择工程保存位置；
3. 程序创建独立的工程目录；
4. 创建工程总体文件和 YAML 存储目录；
5. 将新工程设为当前工程。

工程目录结构：

```text
工程目录/
├── project.json
└── sources/
```

工程总体文件至少保存：

* 工程格式版本；
* 工程名称；
* YAML 文件列表；
* YAML 在工程目录中的相对路径；
* 每个 YAML 的副本数量；
* 控制周期；
* UA 地址；
* UA 端口。

---

## 4.3 打开工程

用户点击“打开工程”后：

1. 打开本地文件选择器；
2. 用户选择已有工程的 `project.json`；
3. 程序读取工程总体文件；
4. 检查工程内 YAML 是否存在；
5. 校验成功后加载工程；
6. 校验失败时显示具体错误，不加载不完整工程。

“打开工程”和“新建工程”必须是两个独立按钮，分别执行不同逻辑。

---

## 4.4 添加 YAML

用户点击“添加 YAML”后：

1. 选择一个外部 YAML 文件；
2. 程序解析该 YAML；
3. 校验 YAML 格式；
4. 读取该 YAML 中的全部位号；
5. 检查位号是否重名；
6. 校验通过后，将 YAML 复制到工程的 `sources/` 目录；
7. 在 YAML 列表中增加该文件，默认副本数量为 `1`。

工程只使用复制到 `sources/` 中的 YAML，不再引用外部原文件。

---

## 4.5 位号重名校验

添加 YAML 前，必须检查：

* 新 YAML 文件内部是否存在重复位号；
* 新 YAML 中的位号是否与当前工程已有 YAML 的位号重复。

发现任何重名时：

* 不允许添加该 YAML；
* 不复制文件到 `sources/`；
* 不修改当前工程配置；
* 显示全部重复位号；
* 显示重复位号所在的文件。

错误提示示例：

```text
无法添加 A.yaml。

发现重复位号：
- level：与 B.yaml 重复
- pressure：A.yaml 内部重复
```

位号重名校验必须在文件复制和工程修改之前完成。

---

## 4.6 YAML 快照规则

添加到工程的 YAML 是工程创建和配置时的文件快照。

规则如下：

* 外部原文件后续修改，不影响当前工程；
* 外部原文件被删除，不影响当前工程；
* 基础模板更新，不自动更新已有工程；
* 已有工程始终使用工程目录中的原有 YAML；
* 用户需要使用新版模板时，应新建工程；
* 程序不得静默替换工程中的 YAML。

---

## 4.7 修改副本数量

YAML 列表中的副本数量可编辑。

交互规则：

* 默认值为 `1`；
* 只允许输入正整数；
* 修改后立即重新计算实例总数；
* 修改后工程标记为“未保存”；
* 点击“保存工程”后写入工程总体文件。

副本生成的实例名称由现有实例命名规则决定。

---

## 4.8 移除 YAML

用户点击“移除”后：

1. 显示确认提示；
2. 确认后从工程配置中移除该 YAML；
3. 删除工程 `sources/` 中对应的 YAML 副本；
4. 重新计算实例总数；
5. 将工程标记为“未保存”。

---

## 4.9 工程校验

工程组态发生变化后，程序执行校验。

校验内容包括：

* 工程总体文件格式；
* YAML 文件是否存在；
* YAML 格式是否合法；
* YAML 内部位号是否重名；
* 不同 YAML 之间位号是否重名；
* 副本数量是否合法；
* 实例名称是否冲突。

正常情况下只显示：

```text
工程状态：校验通过
实例总数：3
```

校验失败时显示错误详情，不常驻展示完整实例列表。

---

# 5. 实时运行

## 5.1 页面布局

页面分为左侧运行控制区和右侧实例区。

```text
┌──────────────────┬──────────────────────────────────────────┐
│ 运行控制          │ 实例列表                                 │
│                  │                                          │
│ 控制周期          │ 实例名 │ 画面模板 │ 详情                 │
│ UA 地址           │                                          │
│ UA 端口           │                                          │
│ 服务状态          │                                          │
│                  │                                          │
│ [启动] / [停止]   │                                          │
└──────────────────┴──────────────────────────────────────────┘
```

左侧为固定宽度的小区域，右侧占据页面主要空间。

页面不设置任何子 Tab。

---

## 5.2 左侧运行控制区

左侧包含：

| 字段    | 说明                     |
| ----- | ---------------------- |
| 控制周期  | 设置内部算法的运行周期            |
| UA 地址 | 设置 OPC UA Server 的监听地址 |
| UA 端口 | 设置 OPC UA Server 的监听端口 |
| 服务状态  | 显示当前服务状态               |
| 启动/停止 | 控制整个工程的实时服务            |

服务状态包括：

```text
未运行
启动中
运行中
停止中
运行异常
```

---

## 5.3 启动服务

用户点击“启动”后，程序依次检查：

1. 当前是否已经打开工程；
2. 工程是否已经保存；
3. 工程校验是否通过；
4. 工程内 YAML 是否完整；
5. 是否存在位号或实例名称冲突；
6. 控制周期是否合法；
7. UA 地址是否合法；
8. UA 端口是否合法；
9. UA 端口是否已被占用。

检查失败时禁止启动，并显示具体原因。

启动成功后：

* 启动工程中的全部实例；
* 启动 OPC UA 服务；
* 服务状态变为“运行中”；
* 控制周期、UA 地址和 UA 端口变为只读；
* “启动”按钮变为“停止”。

---

## 5.4 停止服务

用户点击“停止”后：

1. 服务状态变为“停止中”；
2. 停止当前工程的全部实例；
3. 停止 OPC UA 服务；
4. 完成后状态变为“未运行”；
5. 恢复控制周期、UA 地址和 UA 端口编辑。

切换顶部 Tab 不得自动停止服务。

---

## 5.5 右侧实例列表

实例列表由工程中的 YAML 和副本数量自动生成。

表格包含三列：

| 列    | 说明         |
| ---- | ---------- |
| 实例名  | 当前实例名称     |
| 画面模板 | 该实例对应的画面模板 |
| 详情   | 打开该实例的参数详情 |

画面模板由实例对应的 YAML 或模板定义决定，本页面只显示，不编辑实例默认参数。

不再设置独立的“画面”Tab。

---

# 6. 实例详情

## 6.1 打开方式

用户点击实例的“详情”按钮后：

* 在实时运行页面右侧区域打开实例详情；
* 不创建新的顶部 Tab；
* 不离开实时运行页面；
* 提供“返回实例列表”按钮。

```text
┌─────────────────────────────────────────────────────────────┐
│ ← 返回实例列表                    当前实例：instance_1       │
├─────────────────────────────────────────────────────────────┤
│ 参数名 │ 参数描述 │ 实时值 │ 操作                           │
├─────────────────────────────────────────────────────────────┤
│ level  │ 液位     │ 1.25   │ [选择操作 ▼]                  │
│ sv     │ 设定值   │ 2.00   │ [选择操作 ▼]                  │
└─────────────────────────────────────────────────────────────┘
```

---

## 6.2 参数表

参数表包含：

| 列    | 说明             |
| ---- | -------------- |
| 参数名  | 参数或位号名称        |
| 参数描述 | YAML 中定义的参数说明  |
| 实时值  | 当前内部运行值        |
| 操作   | 对当前参数执行运行时调试操作 |

表格实时刷新参数值。

未启动服务时：

* 可以查看实例和参数定义；
* 实时值显示为空或“未运行”；
* 运行时操作不可用。

---

# 7. 参数运行时操作

参数表的“操作”列使用下拉列表，包含以下功能。

## 7.1 固定 UA 输出值

用户选择该操作后：

1. 输入需要固定的值；
2. 确认操作；
3. OPC UA 向外输出指定值。

执行效果：

* 控制系统内部算法继续运行；
* 参数内部实时值继续变化；
* OPC UA 对外输出值保持固定；
* 页面显示该位号处于“UA 输出固定”状态。

固定输出不得停止或修改内部算法。

---

## 7.2 设置设定值

用户选择该操作后：

1. 打开设定值输入框；
2. 输入框默认值为 `0`；
3. 用户可修改该值；
4. 确认后将设定值写入运行系统。

执行效果：

* 新设定值参与后续算法运算；
* 页面显示当前设定值；
* 写入失败时显示具体错误。

---

## 7.3 修改 UA 质量码

用户选择该操作后：

1. 打开质量码选择列表；
2. 用户选择目标质量码；
3. 确认后修改 OPC UA 对外输出的质量码。

执行效果：

* 不修改内部实时值；
* 不修改 UA 输出的数值；
* 只修改 UA 对外输出的质量码；
* 页面显示当前质量码覆盖状态。

可选质量码由运行时实际支持的 OPC UA 状态决定。

---

## 7.4 操作状态

参数被执行运行时操作后，必须显示明确文字状态，例如：

```text
UA 输出固定：10.0
设定值：5.0
质量码覆盖：Bad
```

不能只通过颜色或图标表示。

已设置的固定输出或质量码覆盖必须支持解除，使位号恢复正常输出。

---

# 8. 用户标准操作流程

## 8.1 单文件组态调试

```text
进入“组态调试”
→ 新建或打开 YAML
→ 编辑配置
→ 执行仿真
→ 查看画面和数据
→ 导出结果
```

## 8.2 实时工程创建

```text
进入“工程组态”
→ 点击“新建工程”
→ 输入工程名称并选择保存位置
→ 添加 YAML
→ 执行位号重名校验
→ 设置副本数量
→ 保存工程
```

## 8.3 打开已有工程

```text
进入“工程组态”
→ 点击“打开工程”
→ 选择 project.json
→ 校验并加载工程
→ 修改 YAML 或副本数量
→ 保存工程
```

## 8.4 实时运行

```text
进入“实时运行”
→ 设置控制周期、UA 地址和 UA 端口
→ 启动服务
→ 在实例列表中选择实例
→ 打开实例详情
→ 查看实时参数
→ 执行固定输出、设置设定值或修改质量码
→ 停止服务
```

---

# 9. 本次取消的界面和功能入口

本次重构后取消：

* 顶部“DSL 工程”名称；
* 顶部“实时运行与 UA”入口；
* “实时运行与 UA”下的“组态、运行、画面”子 Tab；
* 独立“画面”页面；
* 工程组态页中的完整实例列表；
* 工程组态页中的报警规则区域；
* 实时运行页中的单 YAML 旧运行入口。

原“DSL 工程”的具体功能不删除，只将名称改为“组态调试”。

---

# 10. 验收标准

1. 顶部只显示“组态调试、工程组态、实时运行”三个 Tab。
2. “组态调试”仅改名，原功能保持不变。
3. “工程组态”提供独立的“打开工程”和“新建工程”按钮。
4. 工程以本地目录形式保存，包含总体文件和复制后的 YAML。
5. 已有工程不受外部 YAML 或基础模板更新影响。
6. 添加 YAML 前必须检查位号重名。
7. 发现任意重名时，整个 YAML 不得添加。
8. 工程组态页不显示完整实例列表和报警规则。
9. 实时运行页采用左侧运行控制、右侧实例列表布局。
10. 实例表包含实例名、画面模板和详情。
11. 点击详情后在当前页面显示实例参数表。
12. 参数表包含参数名、描述、实时值和操作。
13. 参数支持固定 UA 输出、设置设定值和修改 UA 质量码。
14. 切换顶部 Tab 不得隐藏导航、丢失工程或停止正在运行的服务。
