# Ray 生产环境观测日志说明

## 目标

在不修改 Wails/API 接口和采集业务语义的前提下，记录生产 Ray Dashboard
接口的响应特征、JSON 结构和采集结果，供离线分析与后续兼容开发使用。

## 文件

日志写入配置中的 `LogDir`。相对路径仍按原规则解析为程序所在目录。

| 文件 | 内容 |
| --- | --- |
| `ray_monitor.log` | 原有兼容日志，保留现有排障流程 |
| `app_YYYY-MM-DD.jsonl` | 程序启动、运行时初始化、配置保存和退出 |
| `api_YYYY-MM-DD.jsonl` | Ray HTTP 请求端点、状态、耗时、编码和响应大小 |
| `environment_YYYY-MM-DD.jsonl` | 响应 JSON 结构、结构指纹、服务端和 Ray 版本响应头 |
| `collection_YYYY-MM-DD.jsonl` | 每轮节点、Worker、Actor、Job 和完整性统计 |
| `error_YYYY-MM-DD.jsonl` | HTTP、解析和采集阶段错误 |

文件按运行机器的本地自然日切换。程序启动时清理修改时间超过 30 天的上述
JSONL 文件，不清理 `ray_monitor.log`。

## 环境结构日志

`environment` 日志不保存完整响应值，而是保存字段路径和 JSON 类型。例如：

```json
{
  "msg": "ray_response_schema",
  "cluster": "prod-a",
  "endpoint": "/nodes/{nodeId}",
  "schema_fingerprint": "f36b24d9b87f31a0",
  "schema_changed": false,
  "json_shape": [
    "$.data.detail.workers[]:object",
    "$.data.detail.workers[].pid:number"
  ]
}
```

同一集群、同一端点的结构只在首次出现或结构发生变化时记录。节点 ID 会从
端点中归一化，Actor map 的动态 ID 会记录为 `*`。

## 安全边界

- 不记录请求 Cookie。
- 不记录完整成功响应。
- URL 只记录 scheme 与 host，不记录 user info、query 或 fragment。
- HTTP 错误仍沿用原有行为，最多记录经过换行清理和长度限制的 512 字节响应摘要。
- 日志可能包含集群 ID、主机地址、节点 ID、错误文本和进程统计，传输前仍应按生产数据处理。

## 回传建议

复现或运行观察完成后，提供对应日期的以下文件：

```text
ray_monitor.log
app_YYYY-MM-DD.jsonl
api_YYYY-MM-DD.jsonl
environment_YYYY-MM-DD.jsonl
collection_YYYY-MM-DD.jsonl
error_YYYY-MM-DD.jsonl
```

若文件较多，可整体压缩 `LogDir`。分析时优先使用 `environment` 判断 Ray
接口结构和版本差异，使用 `api` 判断性能与压缩情况，使用 `collection`
判断数据完整性，最后用 `error` 和 `ray_monitor.log` 定位失败原因。
