## 3. 快速上手

```python
from tpt_api import AlgAPI
from tpt_api import cubdata as cub

# 登录测试租户一
api = AlgAPI("https://tpt.supcon.com", timeout=60.0)
api.login("13854389823", "AWSWJ2UW", "AWSWJ2UW")

# 查询当前用户成绩记录
history = cub.get_score_history(api)
print(history["data"])

# 读位号实时值
rt = cub.read_realtime_values(api, ["FICQ_60402.PV", "LIC_60501.PV"])
print(rt["data"])

# 读位号历史值（2 小时跨度，1440 条/位号）
his = cub.read_history_data(
    api,
    tag_names=["FICQ_60402.PV", "LIC_60501.PV", "TE60402.PV"],
    start_time="2026-08-03 18:54:27",
    end_time="2026-08-03 20:54:27",
)
print(his["data"][0]["name"], his["data"][0]["count"])
```

## 4. API 端点清单

### 4.1 位号读写（Tag Value Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `read_history_data` | GET | `/cub-data/tag/readHisData` | 批量读位号历史值（5s 间隔，无分页） |
| `read_realtime_values` | GET | `/cub-data/tag/readValues` | 读位号实时值 |
| `write_tag_value` | POST | `/cub-data/tag/writeValue` | 写入位号实时值（query params） |

**`read_history_data` 实测数据特征**：
- 采集间隔固定 5s，点数 = 时间跨度 / 5
- 2 小时 = 1440 条/位号，响应体 ~1.8 MB（13 个位号）
- 所有位号点数一致、时间戳对齐
- 存在 quality=0 的断连段（value 保位不归零），实测 2h 内有两段 50s 窗口

**`read_realtime_values` 返回字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | str | 位号名 |
| `value` | any | 实时值 |
| `quality` | int | 质量码（192=Good, 0=断连） |
| `timeStamp` | int | 毫秒时间戳 |
| `alarm` | int | 报警状态 |

### 4.2 评分中心（Score Center Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `get_score_history` | GET | `/cub-data/score/getHistoryRecord` | 查询当前用户成绩记录 |
| `run_algorithm` | POST | `/cub-data/score/runAlgorithm` | 运行算法评估（**已废弃**，用 V2） |
| `run_algorithm_v2` | POST | `/cub-data/score/runAlgorithmV2` | 运行算法评估 v2（加载工况，2h 后出结果） |
| `clear_my_records` | POST | `/cub-data/score/clearMyRecords` | 清空当前用户成绩 + 已上传文件 |

**用户成绩记录字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 记录 ID |
| `userId` | int | 用户 ID |
| `score` | float | 评分（保留 5 位小数，评估中为 null） |
| `sci` / `se` / `ssafe` / `ssmi` | float | 评分子指标 |
| `status` | int | 1=评估中, 2=评估完成, 3=评估失败 |
| `algorithmType` | str | 算法类型 |
| `startWorktime` / `endWorktime` | str | 工况时间范围 |
| `algorithmStartTime` / `algorithmEndTime` | str | 算法运行时间 |
| `isBest` | bool | 是否最优成绩 |
| `retryCount` | int | 失败重试次数（上限 2） |
| `count` | int | 次数 |

### 4.3 软测量评分（File Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `get_soft_sensor_score` | GET | `/cub-data/file/score` | 查询最新上传文件及评分 |
| `run_soft_sensor_score` | POST | `/cub-data/file/softSensorScore` | 触发软测量评分（调 concentration_fit_py 算法） |
| `download_template` | GET | `/cub-data/file/template` | 下载模板文件（返回 bytes） |
| `upload_score_file` | POST | `/cub-data/file/upload` | 上传 Excel 预测数据（multipart） |

**上传文件记录字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 主键 |
| `userId` | int | 上传用户 ID |
| `fileName` | str | 重命名后的文件名 |
| `filePath` | str | 磁盘完整路径 |
| `uploadTime` | str | 上传时间 |
| `score` | float | 软测量评分（0-10 两位小数，未评 null） |

### 4.4 评估配置（Eval Config Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `get_eval_config` | GET | `/cub-data/eval-config` | 查询评估配置（单行，id=1） |
| `update_eval_config` | POST | `/cub-data/eval-config` | 更新配置（仅 3 个字段可改） |

**评估配置字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `pracLoadEnabled` | int | 练习工况开关（1=开, 0=关） |
| `examLoadEnabled` | int | 考试工况开关（1=开, 0=关） |
| `evalDurationMinutes` | int | 评估时间段（分钟） |

### 4.5 鉴权调试（Auth Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `get_auth_info` | GET | `/cub-data/auth/info` | 解析 token 返回用户信息 |

### 4.6 用户同步（Auth User Sync Controller）

| 函数 | HTTP | 端点 | 说明 |
|------|------|------|------|
| `sync_auth_users` | POST | `/cub-data/auth-user-sync/sync` | 手动触发从 TPT 同步用户 |

## 5. 响应格式

cub-data 统一响应体与 TPT 标准格式不同：

```json
// cub-data 格式
{
  "code": 200,           // 整数，200=成功
  "message": "操作成功",
  "data": { ... }        // 数据体，null=无数据
}
```

```json
// TPT 标准格式（datahub/users/algorithms）
{
  "code": "00000",       // 字符串
  "msg": "ok",
  "content": { ... }
}
```

由于格式差异，`AlgAPI._request` 在 HTTPS 模式下跳过 code 检查，返回完整响应 dict。调用方通过 `result["data"]` 取数据，通过 `result["code"] == 200` 判断成功。

| 20 | 100% | 1.42s | 14.1 req/s | 逐字节一致 |
| 40 | 100% | 2.59s | 15.4 req/s | 逐字节一致 |
